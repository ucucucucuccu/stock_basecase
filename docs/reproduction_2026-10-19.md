## 遇到的問題與處理

### 1. 環境：Python 3.14、pandas 3.0 —— 沒有問題

原 README 寫 `python3`；這台電腦是 Windows，改用 `python`（venv 放在上一層的 `..\.venv`，不在這個資料夾裡）。全部套件都裝得起來（numpy 2.5.4、pandas 3.0.6、scikit-learn 1.9.1、spaCy 3.8.16、yfinance 1.7.0），沒有遇到相容性錯誤或警告。

所有指令都加了 `-X utf8`：這台電腦的預設編碼是 cp950，而幾支程式開檔時沒有指定編碼；`-I` 會忽略 `PYTHONUTF8` 環境變數，所以用旗標。事後檢查，StockNet 的 25,711 個推文檔全是 ASCII，不加也不會出錯，這只是預防。

### 2. step1 的資料讓 step4 直接崩潰 → 已修正 step1

**症狀：** 用 step1 原樣下載的股價跑 step4，在第一個 ridge 就停下來：`ValueError: Input X contains NaN`（完整訊息在 `logs/step4_crash_with_original_step1_data.log`）。

**原因：** FinMind 在股票「沒有交易的日子」會回傳一列開高低收量全是 0 的資料。60 檔裡有 6 列：

| 股票 | 日期 | 備註 |
|---|---|---|
| 2317 | 2025-07-30 | 報告 3.2 節提到鉅亨網缺這一天 |
| 2884 | 2025-11-05 | 同上 |
| 1101 | 2025-08-13 | |
| 2887、2888 | 2024-08-22 | |
| 3665 | 2026-06-10 | |

這一列的真實振幅變成 ln(前收 ÷ 0)＝無限大，隔天的「前一天收盤」又是 0，一路傳到 HAR 特徵，標準化後變成 NaN。

**修正：** 照報告 3.5 節檢查清單第 2 條（刪除停牌日的假資料：開高低收相同且量為 0；漲跌停鎖死的日子量不為 0，保留），在 `step1_prices.py` 下載後刪掉這些列，並在品質報告加一欄 `dropped_no_trade_rows` 列出刪了哪些。刪掉後，隔天的前一天收盤就是最後一個真實收盤價。這是唯一一處對原始程式的修改。

修正後重新下載一次股價（第一次的檔案留在 `data/_prices_first_run/`）。

### 3. 品質報告的 `abs_logret_over_0.105` 大多是跌停，不是資料錯誤

原 README 說這一欄不是 0 的股票「多半是漏掉的分割或減資，要人工查」。修正後的資料裡，60 檔有 36 檔不是 0，共 87 筆，其中 86 筆是**跌停**：收盤 ÷ 參考價＝0.9000–0.9003，取對數的絕對值是 0.1050–0.1054，剛好落在 0.105 這個門檻上（修正前還多 12 筆，來自問題 2 的全 0 列）。唯一的例外是：

- 3481 群創 2024-08-26：+14.4%，前面 2024-08-15～23 停止交易 7 天，像是減資後恢復交易，但 FinMind 的除權息與分割表格沒有這筆。這一天比研究期間第一天（2024-10-01）早 25 個交易日，超出 HAR 的 22 天回看，不影響振幅模型；正式版應該用 `TaiwanStockCapitalReductionReferencePrice` 補上參考價。

建議把門檻改成 0.11，或先排除「收盤等於跌停價」的日子，否則這一欄幾乎每檔都會亮。這次沒有改，因為它只是報告，不影響模型。

### 4. 洩漏對照（當天盤中新聞）在 step4 原樣輸出裡方向相反 → 是選 α 的雜訊

step4 的固定切分對每個模型各自在驗證期選 α。中覆蓋組 M2 選到 α=100、LEAK 選到 α=10，結果 LEAK 比 M2 低 0.006，看起來和 BC6 的 +0.012 相反。把 LEAK 的 α 固定成和 M2 一樣後，增量是 +0.010（0.007–0.013），和 BC6 一致；walk-forward（α 固定 10）下是 +0.015（0.009–0.020）。權值股相同 α 下是 +0.005（+0.001～+0.009），BC6 是 −0.003（不顯著）——兩邊都很小，報告也沒有拿權值股的這個數字下結論。

建議：比較巢狀模型時，用同一個 α（或在 walk-forward 下比），不要各自選，否則 ΔR² 會混進選 α 的雜訊。

### 5. step4 沒有輸出報告引用的部分數字 → 用補充腳本算

報告 7.1 節引用但 step4 不會輸出的：分組 ΔR² 的信賴區間（+0.050 到 +0.157 這類）、加權指數與 ADR 的跨市場數字。`code/step4_supplement.py` 用和 step4 完全相同的建表程式與 walk-forward 設定算出這些，step4 本身沒有改動。

### 6. 沒有做的部分

- **BC6 瀏覽器版（`bc6_taiwan_browser.js`）沒有執行。** 報告 12.2 節的第 7 週目標和 D2 決策點，都是用 Python 版 step1–step4 重現 BC6；瀏覽器版要在鉅亨網的分頁裡再爬一次 35 分鐘的新聞，而 step2 已經抓到和 BC6 完全相同的 49,958 篇。
- **step5 真正的 embedding：** 見上面 step5，需要你本人同意 Gemma 授權。
- **BC4** 原本就只有統計結果、沒有程式，已被 BC6 的完整兩年資料取代（報告 7.3 節）。

## 和 BC6 不同的地方（數字為什麼不完全一樣）

原 README 已經說明 step4 和 BC6 有兩點不同；這次實際比對下來，差異來源如下：

1. **股價來源：** BC6 用鉅亨網線圖 API，step1 用 FinMind。鉅亨網缺幾天（報告 3.2 節：2308 等缺 2024-12-16），兩邊能用的（股票，交易日）略有不同：測試期筆數權值股 4,693 對 4,672、中覆蓋組 9,162 對 9,125，交易日 236 對 235。
2. **除權息日：** 兩邊都不把這些日子當預測目標，但 BC6 在這些日子不算振幅（HAR 回看時跳過），step1／step4 用交易所參考價算出振幅、留在 HAR 特徵裡；事件日的來源也不同（BC6 是 Yahoo events，step1 是 FinMind 的除權息與分割表格）。
3. **大盤特徵：** BC6 用加權指數的真實振幅，step4 用所選股票的平均。各組的平均低估幅度和 BC6 不一樣（例如中覆蓋組「沒有新聞」的日子 BC6 低估 2.7%、復現 0.2%），可能就是這個原因；組別之間的差距（財報日明顯低估）不變。
4. **台積電 ADR：** BC6 用鉅亨網（缺 14 天，缺的日子另加旗標），step1 用 yfinance（完整）。
5. **固定切分選到的 α 不同**（例如中覆蓋組 BC6 全部 0.1、復現全部 100）。固定切分的 R²（基準為訓練期平均）也比 BC6 高：權值股 0.52–0.53（BC6 0.49–0.51）、中覆蓋組 0.56–0.57（BC6 0.53）；大波動日 AUC 高約 0.01–0.04。這幾項沒有逐一拆解是哪個差異造成的，但都不影響報告的結論（新聞的增量仍然接近 0）。

## 重跑

```powershell
python -m venv ..\.venv
..\.venv\Scripts\python.exe -m pip install -r env\requirements-lock.txt
git clone https://github.com/yumoxu/stocknet-dataset ..\_downloads\stocknet
powershell -ExecutionPolicy Bypass -File run_all.ps1 -SkipDownload   # 用 data\ 裡的股價與新聞，約 5–10 分鐘（這次實測兩次：7.5、4.5 分鐘，結果完全相同）
powershell -ExecutionPolicy Bypass -File run_all.ps1                 # 連股價、新聞都重新下載，約 1 小時
```

- 不加 `-SkipDownload` 時，FinMind 約 182 次請求；免註冊的上限是每小時 300 次，同一小時內重跑會超過，請先到 FinMind 免費註冊並設定環境變數 `FINMIND_TOKEN`。
- 真正的 embedding（step5）：到 https://huggingface.co/google/embeddinggemma-300m 登入並同意授權，在終端機登入 Hugging Face（`hf auth login`，舊版指令是 `huggingface-cli login`），裝 `sentence-transformers` 與 PyTorch（1050 Ti 用 cu126 版），再照原 README 的 step5 指令跑。
